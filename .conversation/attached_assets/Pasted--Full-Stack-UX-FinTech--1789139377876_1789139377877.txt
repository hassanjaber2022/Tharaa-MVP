أنت مهندس برمجيات Full-Stack وخبير UX وأمن معلومات متخصص في تطبيقات FinTech.

أنشئ تطبيق ويب حقيقياً متكاملاً باسم:

ثراء | Tharaa
الشعار النصي: «مستقبلك يبدأ اليوم»

لا تنشئ واجهة شكلية فقط. المطلوب Frontend وBackend وREST APIs وقاعدة بيانات MongoDB ونظام مستخدمين وصلاحيات، مع ربط جميع الصفحات بالبيانات الفعلية.

ابدأ أولاً في Plan Mode:

1. حلل المتطلبات.
2. اكتب Architecture واضحة.
3. قسم التنفيذ إلى مراحل.
4. اعرض Collections وAPI Endpoints والصلاحيات.
5. بعد اعتماد الخطة، ابدأ البناء تدريجياً واختبر كل مرحلة.

فكرة المشروع:
ثراء منصة مالية للشباب من 18 إلى 35 عاماً تساعد المستخدم على تحويل مساهمته الشهرية إلى خطة لبناء احتياط مالي ودخل مستقبلي توضيحي.

ثراء لا يدير استثمارات حقيقية في النسخة الأولية، ولا يحول الأموال، ولا يقدم وعداً بالعائد. التنفيذ المالي المستقبلي سيكون عبر بنك أو شركة استثمار مرخصة.

* TypeScript.
* Vite.
* Tailwind CSS.
* مكونات UI قابلة لإعادة الاستخدام.
* React Router.
* React Query أو TanStack Query لإدارة طلبات API وحالات Loading وError.
* React Hook Form.
* Zod للتحقق من المدخلات.

Backend:

* Node.js.
* Express.
* TypeScript.
* REST API منظمة.
* Controllers وServices وRoutes وMiddleware منفصلة.
* معالجة أخطاء مركزية.
* Validation باستخدام Zod.
* Logging دون تسجيل كلمات المرور أو البيانات الحساسة.

Database:

* MongoDB Atlas.
* Mongoose.
* لا تستخدم Local JSON أو بيانات داخل الذاكرة كبديل عن قاعدة البيانات.
* أنشئ indexes للحقول المستخدمة في البحث والعلاقات.
* استخدم timestamps في جميع Collections.

Authentication:

* إنشاء حساب.
* تسجيل الدخول.
* تسجيل الخروج.
* المحافظة على جلسة المستخدم بعد تحديث الصفحة.
* استرجاع كلمة المرور.
* التحقق من البريد الإلكتروني، أو بناء Mock واضح إذا لم يتوفر Email API.
* تشفير كلمات المرور باستخدام bcrypt.
* لا تخزن كلمة المرور كنص عادي.
* استخدم server-side sessions مع express-session وconnect-mongo.
* خزّن Session ID داخل Cookie من نوع HttpOnly.
* استخدم Secure في Production وSameSite=Lax.
* لا تخزن Authentication Token داخل localStorage.
* طبّق Roles:
    customer
    contributor
    advisor
    compliance
    admin

الصفحات العامة:

1. الصفحة الرئيسية:

* شعار ثراء.
* شرح مختصر للمشكلة والحل.
* زر «احسب مستقبلك».
* شرح المراحل الثلاث.
* الفوائد للمستخدم.
* الفوائد للشريك المالي.
* إخلاء مسؤولية واضح.
* قسم الأسئلة المتكررة.

2. التسجيل والدخول:

* Sign Up.
* Login.
* Forgot Password.
* Email Verification.
* رسائل نجاح وخطأ عربية.
* حالات Loading واضحة.

3. Onboarding:
    اطلب من المستخدم:

* الاسم.
* العمر.
* الدخل الشهري.
* المصروفات الأساسية.
* الالتزامات.
* المدخرات الحالية.
* المبلغ الذي يستطيع دفعه شهرياً.
* العمر المستهدف.
* الدخل المستقبلي المطلوب.
* عدد أشهر احتياط الأمان المطلوب.
* استبيان تحمل المخاطر.

لا تطلب الرقم المدني أو بيانات مصرفية حقيقية.

4. حاسبة المستقبل:
    المدخلات:

* العمر الحالي.
* العمر المستهدف.
* الرصيد المبدئي.
* المساهمة الشهرية.
* مساهمة الأسرة أو جهة العمل.
* الزيادة السنوية في المساهمة.
* الرسوم السنوية الافتراضية.
* التضخم.
* السيناريو الاستثماري.

اعرض ثلاثة سيناريوهات توضيحية:

* متحفظ: 3.5%.
* متوازن: 5.5%.
* نمو: 7%.

اجعل هذه النسب قابلة للتعديل من لوحة الإدارة.

استخدم معادلة Future Value الصحيحة للمساهمات الشهرية، وأضف الرصيد المبدئي والزيادة السنوية في المساهمة.

اعرض:

* مجموع المساهمات.
* النمو التوضيحي.
* القيمة المستقبلية الاسمية.
* القيمة الحقيقية بعد التضخم.
* الدخل الشهري التوضيحي عند الوصول.
* الفرق عند زيادة المساهمة 5 أو 10 د.ك.
* رسم بياني لتطور الخطة عبر السنوات.

عالج حالة معدل العائد صفر، والمدد القصيرة والمدخلات غير الصحيحة.

ضع بجانب النتائج:
«هذه النتائج سيناريوهات توضيحية وليست ضماناً أو توصية استثمارية. قيمة الاستثمار قد ترتفع أو تنخفض.»

5. خطة ثراء:
    قسّم خطة العميل إلى:

أ. احتياط الأمان:

* مبلغ يغطي المصروفات الأساسية لعدد محدد من الأشهر.
* يبدأ العميل ببنائه قبل رفع مستوى المخاطر.
* اعرض نسبة اكتماله.

ب. النمو طويل الأجل:

* وصف توضيحي لمحفظة متنوعة ومتوافقة مع الشريعة.
* لا تعرض أسماء منتجات حقيقية.
* التنفيذ غير متاح في النموذج الأولي.

ج. الدخل المستقبلي:

* الانتقال التدريجي إلى خيارات أكثر ملاءمة للدخل الدوري عند اقتراب العمر المستهدف.
* وضح أنه تصور يحتاج شريكاً مالياً مرخصاً.

لا تستخدم كلمة «آمن» كاسم لمستوى استثماري. استخدم:
متحفظ، متوازن، نمو.

6. لوحة العميل:

* ترحيب باسم المستخدم.
* الهدف الحالي.
* الدخل المستقبلي التوضيحي.
* نسبة اكتمال احتياط الأمان.
* الالتزام بالمساهمة الشهرية.
* آخر المساهمات.
* الرسم البياني للخطة.
* توصية سلوكية بسيطة.
* التنبيهات.
* زر تعديل الخطة.
* زر إيقاف الخطة.
* لا تعرض أرباحاً يومية وهمية.

7. المساهمة العائلية أو مساهمة جهة العمل:

* يستطيع العميل إنشاء دعوة.
* الدعوة تحتوي على Token عشوائي محدود المدة.
* لا تخزن Token الخام، بل خزّن Hash.
* يحدد العميل سقف المساهمة.
* يستطيع المساهم إنشاء حساب وقبول الدعوة.
* يرى المساهم مساهماته فقط.
* لا يرى رصيد العميل أو تفاصيل خطته.
* جميع المساهمات في MVP تجريبية وليست تحويلات مالية حقيقية.

8. التعلم المالي:

* دروس قصيرة من 1 إلى 3 دقائق.
* مواضيع: احتياط الأمان، التنويع، المخاطر، التضخم، الرسوم، والاستثمار طويل الأجل.
* سؤال بسيط بعد كل درس.
* حفظ تقدم المستخدم.
* لا تسمح بتأكيد قرار مرتفع المخاطر قبل إكمال الدرس المرتبط به.

9. التنبيهات:

* انخفاض الالتزام بالخطة.
* عدم تسجيل مساهمة.
* اكتمال احتياط الأمان.
* قرب موعد المراجعة.
* تغير كبير في بيانات الخطة.
* جميع التنبيهات داخل التطبيق في المرحلة الأولى.

10. لوحة الإدارة:

* إجمالي المستخدمين.
* المستخدمون النشطون.
* عدد الخطط المحفوظة.
* متوسط المساهمة.
* Funnel:
    زيارة، حاسبة، تسجيل، حفظ خطة، استمرار.
* Cohorts لمدة شهر و3 و6 و12 شهراً.
* تعديل معدلات السيناريو والرسوم والتضخم.
* إدارة الدروس.
* إدارة الإفصاحات وإصداراتها.
* مشاهدة الحالات التي تحتاج مراجعة.
* سجل Audit Logs.
* لا تسمح للإدارة بمشاهدة كلمات المرور أو Session IDs.

الأمان:

* Helmet.
* Rate limiting لمسارات Authentication.
* CORS مضبوط على رابط Frontend فقط.
* منع NoSQL Injection.
* Zod Validation في Backend.
* التحقق من ObjectId.
* Authorization لكل Route.
* CSRF protection أو التحقق من Origin للطلبات التي تستخدم Cookies.
* إخفاء تفاصيل الأخطاء الداخلية في Production.
* عدم إرسال passwordHash أو tokenHash أو session data إلى Frontend.
* حفظ جميع المفاتيح والروابط الحساسة داخل Replit Secrets.
* استخدم MONGODB_URI وSESSION_SECRET كمتغيرات بيئية.
* أنشئ ملف .env.example يحتوي أسماء المتغيرات دون قيمها.
* لا تضع أي Secret داخل الكود أو Git.
